# KingoAssistant Lite · Windows 会话长久性验收

本文件针对 Lite Alpha。仅允许使用本人学校账号及已获授权的学校接口。
**单元测试与构建成功，不等于已通过学校真实账号验收。**

## 环境与前置检查

- Windows 10/11，使用固定的本机 Windows 账户运行。不要把加密会话文件复制到其他账户或电脑。
- 仅使用通过 CI 的 Lite NSIS Alpha 安装包。旧版 Tk EXE 仍应保留。
- 在任何学校联网请求前，确认已独立核验 `known_year_term.verified`、`known_year_term.identity_binding_verified` 和适用的 `server_policy` 访问限制；默认为 false 是合理的，**不能为通过测试而手工伪造核验结论**。
- 不在问题报告、屏幕截图、CI 日志中提供密码、完整 Cookie、HAR 登录请求或学校个人标识。

## 验收矩阵

| 步骤 | 手动动作 | 正确结果 |
|---|---|---|
| 1 | 首次打开 Lite 工作台 | 无明文密码；未登录，未向学校自动发送请求 |
| 2 | 以本人账号手动登录，**不勾选记住** | 成功时可使用当前会话；关闭并重开后不应出现可恢复令牌 |
| 3 | 手动登录并勾选**记住本机登录** | 仅将学校会话用 DPAPI 加密写入 Windows 用户目录，不保存密码 |
| 4 | 正常关闭 Lite 并重新打开 | 登录状态仍为未登录；若加密令牌仍在本地有效期内，显示免密码继续入口，但**不得自动访问学校** |
| 5 | 点击**免密码继续** | 若本地协议／权限门禁有效，进行一次学校身份回读；账号一致才标记已登录 |
| 6 | 点击**核验会话是否有效** | 进行一次受请求预算约束的身份核验；成功明确显示，身份不符或失效撤销会话 |
| 7 | 点击**退出登录** | 本次进程会话与本机加密会话均删除，重新启动不得出现可恢复令牌 |
| 8 | 学校会话过期／协议未核验／网络拒绝 | 不报登录成功，不无限重试，不自行绕过验证码；身份绑定或频率政策缺失时提前说明原因 |
| 9 | 切换本机登录的学校账号 | 不保留上一账号的可恢复会话；失败时也不能错误标为另一账号已登录 |
| 10 | 启动只读监测后修改课程计划 | UI 与 Rust 后端均拒绝修改；结束任务后才能操作 |

## 明确限制

1. **本地最多保存 7 天，不保证学校服务器会话有效 7 天。**
2. Windows DPAPI CurrentUser 加密不能跨账户／跨电脑还原。
3. 保存登录状态依赖学校真正签发的 Cookie。Cookie 名称不固定，校验依据是同源签名登录和后续身份回读，不是字符串是否含有 `JSESSIONID`。
4. 当前只实现原有签名登录及按需恢复，不包含学校 CAS/喜鹊儿扫码登录；未经学校授权不擅自引入新通道。
5. 当前监测为只读，正式自动选课提交仍未实现。
6. 前端操作日志不得包含密码、Cookie、请求正文；出现错误时只回传有限错误码。

## 发布门禁

- Windows CI：Python 单测（含真实 DPAPI 加解密、跨 Python 进程恢复模拟）、前端 TS 编译、冻结 sidecar 的无凭据自检、NSIS 构建、Artifact 上传均通过。
- 使用本人账号在 Windows 真机完成第 1–10 项，并验证界面、休眠/重启场景的用户交互。
- 验证不存在异常退出后独立遗留的后台监测进程；若仍有问题，在正式版发布前修复。
- 在旧版 Tk EXE 与 Lite 的功能对照清单全部满足前，PR 保持 Draft，**不替换或删除旧版**。
