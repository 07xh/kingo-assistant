# KingoAssistant｜纯接口执行架构（唯一有效方案）

> **决策日期：2026-11-20。** 本文档是当前正式技术方案。历史说明、优化报告或旧 UI 文案与本文冲突时，以本文为准。

## 唯一执行链

`Windows 原生 EXE → 进程内 HTTPS 登录 → 应用自有会话 → 官方课程/轮次/已选接口 → 本地定时及准入校验 → 经验证的官方选课提交 HTTP 接口 → 官方结果回读 → UI 三态反馈`

**网络认证、查询、正式提交均由应用自己的 HTTP 客户端完成，浏览器不参与执行链路。**

## 彻底取消的旧方案

- 浏览器自动点击、Selenium、Playwright、CDP 或模拟操作。
- 浏览器登录 + HTTP 提交混合路线、浏览器 Cookie 导入、手动官网预约、到点打开官网及浏览器兜底。
- 使用移动端非授权接口绕过限制、直接回放历史 HAR、猜测提交字段、并发刷写、绕过验证码、认证或服务端请求限制。

Windows 运行时已在独立重构分支移除“手动官网备用”导航、预约回调和自动浏览器打开模块，应用会话检查迁入工具页。历史文档与 Git 提交仍可用于审计，不构成可重新启用的执行方案。

## 模块职责

1. **NativeAuth**：经学校许可且独立验收的 HTTPS 登录协议，在 EXE 内完成账号认证。正常处理校方规定的验证码、CAS 或 MFA；无法合法处理时停止，不以浏览器兜底。密码等凭据不写入配置、日志、Git。
2. **SessionManager**：进程内管理本人会话，独立官方身份回读确认登录；会话过期、身份不一致立即停止。
3. **CatalogReader**：合规读取学期、轮次、课程目录、教学班标识、已选结果及经确认的余量字段。不得把计划人数、容量或 HTTP 200 推断成实时可选名额。
4. **Preflight**：校验学校许可、请求预算、有效时间窗、课程冲突、真实课程及教学班 ID、现有选课记录、提交协议证据。
5. **ScheduledExecutor**：仅在校方允许自动提交、本人明确授权、全部门禁通过时，向已验证的正式选课 HTTP 接口发送一次待确认提交；不执行浏览器交互、并发写入或盲目重试。
6. **ReadbackVerifier**：从官方已选记录确认提交结果，分为**成功 / 失败 / 结果不确定**。网络超时或模糊响应先对账，禁止重复提交。
7. **WindowsUI**：仅负责课程配置、时间、登录入口、实时状态和诊断。HTTP 操作放在工作线程中，不阻塞桌面 GUI。

## 真实接口验收顺序

1. 核实学校是否允许该认证及自动提交方式，确认正式时间和访问限额。
2. 本人合法账号验证进程内 HTTP 登录、身份回读、会话续用和过期处理。
3. 只读核验当期课程目录、教学班身份、选课时间窗、已选结果及余量语义。
4. 在学校许可的环境或时间窗验证正式提交协议、错误码和官方结果回读；不猜参数、不作未经授权的测试提交。
5. 经过端到端 Windows 验收后才允许启用真实提交按钮。离线模拟、CI 构建及一次 HTTP 成功响应均不是正式提交成功的证据。

## 当前实施状态

Windows 已有进程内登录和部分只读学校接口；选课 FSM、定时计划及离线状态记录已存在。**正式 NCWU 选课提交接口和业务回读尚未完成端到端验收，生产写入必须继续禁用。** 本文档更新的是目标架构，不宣称浏览器旧代码已经实际删除。

## 完成标准

只要登录、读取、提交或确认中任一步依赖浏览器，即视为未完成纯接口迁移。必须在学校允许的前提下，完成纯 HTTP 合法认证、精确课程匹配、单次正式提交及官方回读闭环。
