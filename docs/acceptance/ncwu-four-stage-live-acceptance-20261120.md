# KingoAssistant｜纯 HTTP 四阶段真实接口验收

2026-11-20。目标是 **真实可证实的学校接口闭环**，不新增浏览器、刷请求引擎或模拟成功状态。本文是未完成项目的验收约束清单，不是已通过的验收报告。

## 1. EXE 自有会话登录

**当前代码**：`core/ncwu_signed_login.py` 使用本机 HTTP 客户端，按已观察的官方网页签名流程执行，并通过同一客户端的 `showYearTerm.action` 检查账号。验证码、MFA、学校拒绝访问均不绕过。

**新增（本 PR）**：`NativeLoginResult.stage` 仅包含受控的阶段编码；`message` 会显示失败位于「登录页读取 / 签名脚本 / 临时密钥 / 服务器时间参数 / 本机签名 / 官方登录响应 / 账号身份回读 / 会话绑定」哪一阶段。阶段与结果均不包含用户账号、密码、Cookie、原始 URL 查询或服务器响应体。

**本人真实账号验收尚需**：在学校许可和实际适用的登录协议下进行一次正常登录，确认当期签名及验证码要求、认证响应和 `userCode` 账号绑定，并确认合法登录之后确实能访问本人受保护的学校资源。*仅凭历史 HAR、HTTP 200 或 synthetic 单元测试不能确认本人已登录。*

## 2. 课程与教学班的准确匹配

**当前代码**：`core/ncwu_plan_alignment.py` 将课程计划中的内部标识与用户志愿对照；`core/ncwu_live_target_review.py` 只给出 S202 展示页课程候选；`core/ncwu_selected_target_review.py` 只给出历史记录候选。

**未完成**：用同一真实账号、学期、当期 S202 轮次的数据证实志愿 `course_id` 和**内部教学班 `skbjdm`** 的唯一映射，明确区别展示编号 `skbh`。计划容量、历史状态码、展示行命中不可直接转换为实时余量或已选事实。信息重复、冲突或缺失时必须显示未知。

## 3. 经过许可的正式提交协议

**当前代码**：`core/ncwu_submission_transport.py` 只接受已有的、严格匹配账号/学期/轮次/目标的单次表单；`core/ncwu_submission_gateway.py` 要求有效证据、本人授权和正式窗口准入。

**未完成**：学校是否允许此类自动请求以及访问预算；在允许的时间与环境内，由实际第一方流程核实 `items` 与内部教学班 `skbjdm` 的一对一关联、当前会话字段及服务端业务错误语义。不得以猜测字段、历史 HAR 静态重放或请求连发替代合同验收。缺失即禁止提交。

## 4. 官方结果回读

**当前代码**：`core/ncwu_exact_readback.py` 和现有 `core/ncwu_verified_readback_bridge.py` 要求当次、同账号/学期/轮次、`skbjdm` 级记录与证据摘要；普通 S202 HTML 候选和 200 响应不会被提升为成功。当前仍未接通真正经许可的权威记录读取器。

**未完成**：核实具有权威选课结果语义的当前轮次第一方读取接口及其确切字段。提交后结果必须按官方精确课程/教学班记录确认，未知或超时保持待核验、禁止重复提交。

## 验收顺序与隐私

- 不改变现有「纯 HTTP 登录 → 权限和课程匹配 → 单次提交 → 权威回读」链路。
- **先完成登录和真实只读匹配，再推进正式写契约与结果回读**；前两项通过也不授权后两项。
- 真实账号/密码、Cookie、动态签名参数、学号、完整 HAR 和包含个人资料的 HTTP 响应均保留在本人的本地受控环境。共享和提交到公开 GitHub 的仅限无个人信息的结构性摘要。
- 仓库的离线和 CI 通过只说明代码行为符合模拟合同，不表示真实学校账号或生产写入已通过验收。
- 主分支已通过 #83 合入可选提前课表预检和延后结果核验协调逻辑。这些属于离线测试通过的执行机制，**并不构成当前账号的真实选课协议验收**；本次登录诊断不改动该执行链。

## 本 PR 新增测试

`cd clients/windows/source && python -m unittest tests.test_ncwu_login_phase_diagnostics -v`

测试仅使用 `httpx.MockTransport` 和合成账号；覆盖 429/访问限制、动态脚本变化、身份回读不一致、官方挑战要求以及状态输出不泄露凭据。真正的用户级登录验收需要在学校许可的环境中单独完成。

## 2026-11-20 安全与验收状态补强

- Windows「验收详情」将四项**本地证据登记**与四阶段**真实接口验收**分开显示。即使 EXE 当前有已经回读身份的内存会话，也不能据此判定课程、提交或结果回读已验收；提示只表示内存中的当前状态，服务端会话是否有效仍需按学校许可核对。
- 未经官方核实的教学班唯一映射、正式单项表单来源、业务成功/拒绝响应及权威回读仍均标为未完成。GUI 自动提交按钮和现有写入门禁保持原状态。
- `PreparedNCWUSubmission` 的调试表示现已脱敏；学号、轮次、`items`、`hidOption` 等表单信息不通过默认 `repr` 输出。控制字符（包括空字节、CR/LF 和 DEL）在本地表单构造时拒绝，网络请求前即可失败。
- 这些变更只完善本地隐私与诊断，不增加真实学校写请求、请求速率、接口猜测或权限绕过；使用虚构数据执行离线单元测试与 Windows 打包冒烟验证。
