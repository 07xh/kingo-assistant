# 北化课表参考参数与 KingoAssistant 离线调度测试

## 证据边界

此前由用户提供的北化课表 1.0.8.3 APK 静态分析发现：
- 一条默认重试间隔为 1500 ms，另一条启动分支为 2000 ms；
- 默认有 2 个并行工作线程；
- 可以接受自定义间隔，但没有核实其可配置的最小值；
- **没有实测 APK 的 HTTP RPS、最快成功速度，也没有获取学校授权速率信息**。

因此 **1.5 秒、2 工作线程仅作为本地参考场景**，不应宣称是已核实的最高速度或获得学校许可的查询频率。两个同时调度的模拟任务，也不表示对同一门课重复查询有实际收益。

## 此次新增

Windows 图形界面 → **离线工具 → 北化课表参数 · 离线调度测速**

该工具在本机用 asyncio 模拟两条工作流水线，每条按单调时钟以 1.5 秒间隔启动 4 个模拟任务，每次模拟 120 ms 处理时间。GUI 使用后台线程，避免冻结窗口。

报告：
- 总模拟任务数、完成数及最大同时处理数；
- 同一工作线程的平均发起间隔（ms）；
- 相对预期调度时刻的最大发起延迟（ms）；
- 理论调度事件速率（2 / 1.5 ≈ 1.33 次/秒），**不等于 HTTP 请求吞吐量**。

该模块完全不创建网络客户端，不登录学校、不发起课程查询、不触发选课，也不访问通知通道。可在源代码目录用下列命令独立演练：

```powershell
python -m core.offline_benchmark
python -m unittest tests.test_offline_benchmark -v
```

## 保留的真实接口约束

- Windows 的 `main.validate` 和 `core.desktop_settings` 继续限制在线查询为 **60–3600 秒**。
- `core.scheduler` 仍保持单轮只读课程目录查询，不会改为多线程重复请求。
- 遇到服务器的 403 / 429 限制仍停止，验证码与登录验证仍走官方流程。
- 华水真实课程列表和名额接口尚未完成验收；选课提交仍未实现。

## 验收解释

离线调度测试用于观察本机事件循环的基本调度能力，并**不能**证明在校园网络条件下能达到相同速率，也不能预测选课成功概率。下一步如需真实读取，应先取得官方许可的访问规则、核实只读目录端点，并在其允许范围内做低频、可停止的测试。
