# S202 真实表单来源适配边界（2026-11-20）

## 本次实现

新增 core/ncwu_verified_form_provider.py，提供 VerifiedS202FormProvider。

- 接收明确注入的、独立验收的第一方“当前会话正式选课表单读取器”，其产物为 CurrentS202FormObservation。
- 读取前后重新核对 EXE 自有账号、学期、学校来源、内部学号、轮次和会话；拒绝期间切换账号或轮次。
- 读取前后核对 official_write_verified 证据摘要；拒绝被撤销或替换的验收文件。
- 严格要求唯一课程代码 + 内部教学班标识 skbjdm；不能用展示班号 skbh、历史 HAR、S202 2568 展示表或固定模板替代。
- 只接受本次 await 时间内生成的证据，并核对其唯一目标、当前会话、原站正式提交路径、原始字段及映射证据。
- 生成原有 PreparedNCWUSubmission 并交给 NCWUEvidenceBoundGateway；由提交引擎另行检查持久化意图、四项独立验收、学校许可、请求预算和最终官方回读。
- 敏感表单、学号、会话和映射原始字节不通过 repr 输出；模块本身无学校 HTTP、无表单猜测、无提交动作。

相应离线测试位于 tests/test_ncwu_verified_form_provider.py，使用虚构字段和身份验证。

## 本次没有完成的事情

**这不是当前华水生产接口的正式验收，也不是可直接抢课的 EXE。**

正式选课接口路径已被先前材料识别，但目前没有一份经学校许可、同账号同轮次、精确绑定 items 与内部 skbjdm 的第一方成功表单契约；也没有能够确认当次 S202 提交的权威精确已选记录读取器。已知旧结果候选和现有 selected-count/HTML 页不能冒充权威记录。

因此：
- 没有注入真实学校表单读取器、没有从原站生成生产表单；
- 没有注册正式写入源至 Windows 自动提交入口；
- 没有修改默认 dry_run、protocol.verified 或四项 attestation 门禁；
- 不把当前构建成功称作生产选课成功。

## 下一步真实验收（仅在学校允许的环境）

1. EXE 本人账号在当期官方流程完成正常登录与权限验证。
2. 核实本次教学班唯一映射、items/hidOption 的第一方动态来源及服务端业务错误语义。

4. 通过学校明确允许的测试流程验证后，才在 Windows GUI 内注册生产源；禁止使用静态历史请求、猜测参数、并发刷写、未经许可的探测或绕过验证码。

此变更为生产源接入提供了可测试的接口契约，但不会自动授予学校端访问、自动提交权限或真实成功状态。
